# User requirements (URS)

What RegIntel must do for its answers to be usable as records in a regulated (GxP) setting. The
ideas come from 21 CFR Part 11 and EU GMP Annex 11: records are attributable, accurate, complete,
protected against undetected change, and reproducible. RegIntel is a portfolio system, not a
validated product; this pack shows how each requirement links to evidence.

Each requirement is traced to its controls and evidence in [traceability.md](traceability.md).

| ID | Requirement | Why |
|---|---|---|
| URS-01 | Every statement shown to a user is supported by text quoted verbatim from a retrieved source. | Accuracy: no unsupported claim is presented as guidance. |
| URS-02 | Every number in a shown statement appears, by value, in that statement's quotes. | Accuracy: numbers are the most consequential and most often wrong. |
| URS-03 | A statement that goes beyond its quotes (scope, obligation, cause) is not shown. | Accuracy: verbatim quotes can still support a false conclusion. |
| URS-04 | When the sources do not answer the question, the system declines instead of answering. | Accuracy: an abstention is safer than a plausible guess. |
| URS-05 | Instructions planted in a question or in a retrieved passage do not change the system's behaviour. | Integrity of the record against manipulation. |
| URS-06 | FAERS statistics and terminology codes are computed from data, never generated by a model. | Accuracy of quantitative safety information. |
| URS-07 | Live external data (openFDA) is cited only when it was actually retrieved; an outage never produces a cited label or recall. | Accuracy under partial failure. |
| URS-08 | Every answer produces an audit record, written before the answer is released; if it cannot be written, the answer is withheld. | Completeness (Part 11 §11.10(e)). |
| URS-09 | An audit record identifies who asked (the API key's id, never the key), when, the question, the route, the sources with their checksums, the models and prompt versions, every verification decision, latency and tokens. | Attributable and reproducible. |
| URS-10 | Changing, removing or reordering an audit record is detectable, and the first affected record is reported. | Protection against undetected change (Annex 11 §9). |
| URS-11 | An audited answer can be replayed: its sources rebuilt and checked against their checksums, and its draft re-verified with the same decisions. | Reproducibility. |
| URS-12 | Every answer names the versions of the prompts that produced it, and a prompt cannot change without a new version. | Change control. |
| URS-13 | No change reaches production without passing tests, security scans and an evaluation gate against a recorded baseline. | Change control and regression protection. |
| URS-14 | Access to the API requires a key; requests are rate-limited per client. | Access control (Part 11 §11.10(d)). |
| URS-15 | Corpus documents are verified by checksum before they are indexed. | Integrity of the source data. |
